# Final Cut rotated anamorphic format divergence — 2026-09-19

The native Final Cut Pro 12.3 round trip preserves three point findings, exact
24 fps timing, 48-frame duration, note text and source-media bytes, but changes
the asset format from 240 × 180 to 180 × 240. The browser clip keeps its original
240 × 180 format. Both formats retain 4:3 pixel aspect. This is **not** accepted
geometry interoperability: the previous comparator incorrectly reported an
exact match because it only inspected the browser clip's format.

The comparator now checks the asset's raster, pixel aspect and frame duration
independently. The retained case exits 1 with only `assetRaster` false. A native
editor's format normalization may be intentional; this result does not by itself
prove the appropriate exporter correction. Display aspect and geometry remain
an open acceptance gate rather than silently treating the difference as harmless.

## Production generation and native workflow

1. Run the new
   `GeneratedMediaFixtureTests/testFinalCutProExportsRealPortraitAnamorphicAndTransformedSources`
   test with
   `TEST_RUNNER_FCP_GEOMETRY_FIXTURE_OUTPUT=/private/tmp/aagedal-fcp-geometry-20260919`
   passed to `xcodebuild test`. The output directory must already exist and the
   ten destination XML files must not exist. The test reads the existing fixtures
   generated by `scripts/generate-test-fixtures.sh` through production
   `MetadataService`, creates snapshots and calls the production exporter.
2. Import the unchanged `rotate-90-par.fcpxml` using **File → Import → XML** in
   Final Cut. This imports into the existing disposable
   `Aagedal FCP 5994 DF Acceptance 20260919` library and its `Aagedal Compare Review`
   event; it is not a new isolated library. Prior retained Phase 114 XML is unchanged.
3. Select only `rotate-90-par.mp4 vs rotate-90-par.mp4 Review` in the browser.
   The viewer reports 240 × 180 / 24 fps and shows a portrait image with green and
   yellow above red and blue. This confirms visible rotation, not measured display
   aspect correctness. No timeline project is involved.
4. Use **File → Export XML**, General metadata, Current Version (1.14), and save
   `rotate-90-par-roundtrip.fcpxmld` in the temporary output directory. Its unmodified
   `Info.fcpxml` is retained as `returned.fcpxml`; the imported XML is `original.fcpxml`.

The asymmetric source has a 240 × 180 coded raster, 4:3 pixels and 90-degree
display rotation. The test covers ten actual generated files: landscape,
portrait, anamorphic, rotated anamorphic, 180/270-degree rotation, and four
reflections. All preserve their expected coded raster/PAR, rate, source URL,
duration and first/adjacent/final marker positions in the exporter. Only the
rotated anamorphic case was imported/re-exported natively in this phase.

The first command deliberately exits 1. `--verify-media` requires the original
local fixture and native library copy; their equal SHA-256 hashes are retained
in `comparison.json`. XML-only regression tests do not imply media verification.
`provenance.json` binds the base commit plus changed test/comparator hashes,
exporter, metadata service, package lock, fixture and XML files. `test-summary.json`
records 36 focused Debug tests passed with zero skips, failures or runtime
warnings. All ten generated exports pass Final Cut's installed FCPXML 1.9 DTD;
all twelve Python comparator regressions and the complete script-validator gate pass.

The initial test run used `0s` rather than the exporter's equivalent `0/1s` in
its expected string; the corrected run is the evidence above. The first sandboxed
Xcode attempt could not access compiler caches and did not run tests.

This uses the same source for both review sides and plain single-line point
notes. It establishes neither distinct-source comparison, inclusive/grouped
ranges, whitespace preservation, native player UI export, other native geometry
cases, spoken accessibility, nor release-candidate acceptance. No shipping app
behavior changes in this phase.
